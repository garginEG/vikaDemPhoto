# Victoria Photography — сайт + админка

Сайт фотографа Виктории (Москва). Три страницы: о фотографе, студийная съёмка, корпоративная съёмка. Плюс **админ-панель**, где Виктория сама добавляет фото в портфолио и меняет цены — изменения видны всем посетителям сразу.

## Стек

- **Frontend**: HTML5 + CSS3 + Vanilla JS — статика, грузится мгновенно
- **GSAP + ScrollTrigger** — анимации появления и параллакс
- **Lenis** — плавный скролл
- **Supabase** — бэкенд: PostgreSQL (цены, метаданные), Storage (фото), Auth (логин админки)
- **Netlify** — хостинг
- **Masonry layout** — фото любого размера автоматически выстраиваются в колонки

## 🚀 Запуск: пошагово

### Шаг 1. Регистрация в Supabase (3 минуты)

1. Открой [supabase.com](https://supabase.com), нажми **Start your project**
2. Войди через GitHub (или email)
3. **New project**:
   - Name: `victoria-photo`
   - Database Password: придумай надёжный, сохрани
   - Region: `Frankfurt` (ближайший к Москве из бесплатных)
   - Pricing: **Free**
4. Жди ~2 минуты пока проект создастся

### Шаг 2. Настройка таблиц и хранилища (1 минута)

1. В Supabase Dashboard слева: **SQL Editor**
2. Нажми **New query**
3. Открой файл `supabase-setup.sql` из проекта, скопируй всё содержимое и вставь в редактор
4. Жми **Run** (или `Ctrl+Enter`)
5. Должно появиться "Success. No rows returned"

Это создаст таблицы `portfolio` и `pricing`, storage bucket `portfolio` и настроит права доступа.

### Шаг 3. Создание пользователя-админа (1 минута)

1. Слева: **Authentication** → **Users** → **Add user** → **Create new user**
2. Email: `victoria@example.com` (любой)
3. Password: придумай надёжный — **это и есть пароль для входа в админку**
4. Поставь галочку **Auto Confirm User**
5. Жми **Create user**

### Шаг 4. Подключение ключей (30 секунд)

1. Слева: **Settings** (шестерёнка) → **API**
2. Скопируй:
   - **Project URL** (вида `https://abcdefghi.supabase.co`)
   - **anon public** ключ (длинная строка, начинается на `eyJ...`)
3. Открой `js/supabase-client.js` в любом редакторе
4. Замени `YOUR-PROJECT-REF.supabase.co` на свой URL
5. Замени `YOUR-ANON-PUBLIC-KEY` на свой ключ
6. Сохрани

### Шаг 5. Локальный тест

Открой `index.html` двойным кликом — сайт должен заработать. Перейди на `admin.html` → войди с email и паролем из Шага 3.

> **Важно про CORS**: Supabase может ругаться, если открыть с `file://`. Если так — запусти локальный сервер:
>
> ```powershell
> cd victoria-photo
> python -m http.server 8000
> ```
>
> И открой `http://localhost:8000`.

### Шаг 6. Деплой на Netlify

1. [app.netlify.com/drop](https://app.netlify.com/drop) → перетащи папку `victoria-photo`
2. Получаешь ссылку вида `https://random-name.netlify.app`
3. В Supabase: **Authentication** → **URL Configuration** → добавь свой Netlify-домен в **Site URL** и **Redirect URLs**

Готово. Сайт живёт, админка работает, изменения видят все посетители.

## 👩‍💻 Как пользоваться админкой (для Виктории)

### Войти

`https://твой-сайт.netlify.app/admin.html` — email и пароль из Шага 3.

### Добавить фото в портфолио

1. Вкладка **Портфолио**
2. Перетащить фото в зону загрузки (можно несколько за раз)
3. Дождаться завершения
4. Фото сразу появятся на сайте

Фото автоматически выстраиваются по 3 колонкам **masonry** — никаких пробелов, любые пропорции ложатся красиво.

### Удалить фото

Карточка фото → кнопка **Удалить** → подтвердить. Фото удалится из портфолио И из хранилища.

### Изменить цены

1. Вкладка **Цены**
2. Меняешь название, цену, длительность, пункты "что входит", текст кнопки
3. Можно поставить галочку **Выделить как основной тариф** — он подсветится золотым на сайте
4. Жмёшь **Сохранить** под нужным тарифом

## ✅ Что хорошо

- **Никаких бэкенд-разработок** — Supabase делает всю чёрную работу
- **Бесплатно** — лимитов Free-тарифа Supabase хватит с запасом (500 МБ БД, 1 ГБ Storage, 50 000 auth-пользователей/мес)
- **Безопасно** — anon-ключ Supabase можно показывать миру: писать/удалять может только залогиненный пользователь (Row-Level Security)
- **Изменения мгновенные** — не нужно пересобирать сайт или перезаливать на Netlify

## 💡 Что можно улучшить позже

## 🛡 Что НЕ делать

- **Не использовать `service_role` ключ** на фронте — он даёт полный доступ к БД в обход RLS. Только `anon public`.
- **Не коммитить** `js/supabase-client.js` в публичный GitHub с реальными ключами (хотя anon ключ безопасен — это хорошая привычка)
